# 친구·동호회 예측방 — 기능 정리 (구현 전)

> 상태: **초안 / 미구현**  
> 목적: 구현 전에 범위·용어·화면·규칙을 고정한다.  
> 기준일: 2026-08

---

## 1. 한 줄 정의

**공개 실황 예측은 그대로 두고**, 홈에 **초대 전용 「친구·동호회 방」**을 추가한다.  
같은 타석 예측을 함께 하며, **방 멤버끼리만** 순위·소속감을 나눈다.

---

## 2. 두 가지 입장 경로 (병행)

| 경로 | 홈 UI | 대상 | 역할 |
|------|--------|------|------|
| **A. 공개 예측** | 기존 「예측게임 하러가기」(+ 빠몽이) | 모든 로그인 회원 | 지금과 동일 — 오늘 실황 타석 예측 |
| **B. 친구·동호회 방** | **신규 버튼** (예측 버튼 **아래**) | 초대받은 사람만 | 같은 예측 + **방 단위 순위/멤버** |

- A와 B는 **대체 관계가 아님**. A는 유지, B는 추가.
- 빠몽이 캐릭터는 홈 왼쪽에서 **지금보다 약간 위**로 배치해, 아래 버튼 공간을 확보한다.

---

## 3. MVP에 넣는 것 / 넣지 않는 것

### 3.1 MVP에 포함

1. 홈: 캐릭터 상향 + 「친구·동호회 방」 버튼  
2. 방 목록 (내가 만든 방 / 내가 들어간 방)  
3. 방 만들기 (방장)  
4. **카카오톡 초대 링크** (초대받은 사람만 입장)  
5. 방 안에서 **공개와 같은 오늘 경기·타석 예측** 참여  
6. **방 멤버만 보이는 순위** (적중·포인트 등 단순 집계)  
7. 방장: 멤버 내보내기, 방 종료(또는 비활성)

### 3.2 MVP에서 제외 (이후 검토)

| 항목 | 이유 |
|------|------|
| 제목만 보고 **누구나 검색 입장** | 어뷰징·분쟁 위험 → 2단계 |
| 나이·지역 **강제 인증 입장** | 인증·허위 입력 문제 |
| 방마다 **별도 예측 풀·별도 정산** | 운영·실황 연동 복잡도 큼 |
| 방 전용 채팅 | 일정·검수 부담 (원하면 Phase 2) |
| 방 참가비 / 시즌 리그 | 정책·정산 별도 설계 필요 |

---

## 4. 입장 방식 결정 (비교 결과)

| 방식 | MVP | 설명 |
|------|-----|------|
| **초대 전용 (카카오 링크)** | ✅ 채택 | 방장이 공유한 링크(+토큰)로만 입장 |
| 제목 공개 검색 입장 | ❌ 보류 | Phase 2에서 비밀번호·승인제와 함께 검토 |
| 응원팀·나이·지역 **강제 필터** | ❌ 보류 | MVP에서는 **태그(표시용)** 만 |

**원칙:** 입장의 문은 **초대** 하나. 태그는 “이런 방입니다” 안내일 뿐, 입장을 막지 않는다.

---

## 5. 방 정보 구조

### 5.1 필수

| 필드 | 설명 |
|------|------|
| 방 이름 | 목록·초대 미리보기에 노출 |
| 방장 | 개설자 (회원) |
| 초대 토큰 / 링크 | 카카오 공유용, 추측 어려운 값 |
| 상태 | `open` / `closed` |
| 생성·종료 시각 | |

### 5.2 선택 (소개·태그)

| 필드 | 설명 | 강제 여부 |
|------|------|-----------|
| 한 줄 목적/소개 | “동호회 정기 모임”, “LG 같이 보기” 등 | 표시만 |
| 응원 팀 | 단일 또는 없음 | 표시만 |
| 나이대 | 예: 20대 / 30대 / 무관 | 표시만 |
| 주거·활동 지역 | 예: 서울 / 부산 / 온라인 | 표시만 |
| 정원 | 기본 20, 상한 예: 50 | 초과 시 입장 거부 |

### 5.3 정리되지 않던 생각을 이렇게 나눔

```
방 = 공간(이름·방장·초대)
   + 소개(목적 한 줄)
   + 태그(팀·나이·지역) ← 검색·안내용, 입장 조건 아님
   + 활동(같은 실황 예측 + 방 순위)
```

---

## 6. 예측·정산 모델 (MVP)

**채택: “같은 실황, 방 단위 소속·순위만”**

- 타석 예측·포인트 차감·배당 정산은 **기존 공개 예측과 동일** (동일 Match / 동일 live-auto·운영자).  
- 방에 들어오면 “이 계정은 지금 이 방 소속”으로 표시.  
- **방 순위** = 방 멤버만 모아 오늘(또는 방 개설 기간) 적중 수·순이익 등 단순 집계.  
- 방마다 따로 베팅 풀을 만들지 **않음**.

이후(Phase 2+)에서 “방 전용 풀”을 검토할 수 있으나, MVP 범위 밖.

---

## 7. 사용자 흐름

### 7.1 방장

1. 홈 → 「친구·동호회 방」  
2. 「방 만들기」 → 이름·소개·태그·정원  
3. 「카카오로 초대」 → 공유 문구 + 딥링크/웹 링크  
4. 방 안에서 공개와 같이 예측 참여  
5. 필요 시 멤버 강퇴 / 방 종료  

### 7.2 초대받은 사람

1. 카카오 메시지 링크 탭  
2. 미로그인 시 로그인 후 복귀  
3. 유효한 초대 + 정원 여유 + 방 `open` → 자동 입장  
4. 방 화면에서 예측 참여 · 방 순위 확인  

### 7.3 초대 없이 URL만 아는 경우

- 유효 토큰 없으면 **입장 불가** (목록 검색으로 못 들어옴).

## 8. 화면 목록 (MVP)

| 화면 | 내용 |
|------|------|
| 홈 (왼쪽) | 빠몽이(상향) / 예측게임 하러가기 / **친구·동호회 방** |
| 방 허브 | 내 방 목록, 방 만들기 |
| 방 만들기 | 이름·소개·태그·정원 |
| 방 상세(대기/허브) | 멤버, 초대, 순위, 「예측 참여」 |
| 예측 | 기존 `/prediction` 재사용 + **현재 방 배지**(소속 표시) |
| 초대 랜딩 | 토큰 검증 → 입장 또는 오류 |

---

## 9. 권한·규칙

| 주체 | 가능 |
|------|------|
| 방장 | 생성, 초대, 강퇴, 종료, 소개/태그 수정 |
| 멤버 | 입장(초대), 퇴장, 예측, 방 순위 조회 |
| 비멤버 | 초대 링크 없이는 불가 |
| 게스트 | MVP에서는 **정회원만** 방 생성·입장 권장 (정책으로 확정) |

- 한 사람이 **동시에 여러 방 소속** 가능 여부 → MVP는 **가능**, 화면에는 “현재 보고 있는 방”만 강조.  
- 방 종료 후 재입장 불가. 순위는 읽기 전용으로 남을지 여부는 구현 시 `closed` 정책으로 확정.

## 10. 카카오 초대

- 공유 내용 예: `[빠몽이] {방이름} — {한줄소개}` + 링크  
- 링크: `https://ppamong.com/rooms/join/{token}` (앱 스킴 병행은 추후)  
- 토큰: 추측 불가, 방 종료·재발급 시 무효화 가능  
- 카카오 SDK / 공유 API 연동은 구현 단계에서 확정 (웹 공유 URL만으로도 MVP 가능)

---

## 12. 공개 예측과의 관계 (운영)

- 공개 예측 조건(오늘 경기 등록, 실황 ON, 예측 열림)은 **그대로**.  
- 친구방도 **같은 조건**이 없으면 타석 예측은 대기 상태.  
- 친구방은 “사람 모으기·순위”이고, **실황 엔진을 대체하지 않음**.

---

## 13. 구현 착수 전 확정 체크리스트

구현 시작 전에 아래로 답만 고정하면 된다.

- [ ] 게스트 방 참여 허용 여부 → **제안: 불허(정회원만)**  
- [ ] 1인 동시 소속 방 수 상한 → **제안: 5**  
- [ ] 정원 기본/최대 → **제안: 20 / 50**  
- [ ] 방 순위 집계 단위 → **제안: 당일(KST) 적중 수·순이익**  
- [ ] 방 종료 후 데이터 → **제안: 순위 7일 조회 후 보관 또는 삭제**  
- [ ] 카카오: 앱 공유 vs 웹 링크만 → **제안: MVP는 웹 링크 공유**
